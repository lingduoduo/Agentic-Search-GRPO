# Description judgeability implementation

## User requirements
Evaluate judgeability with fixed corpus tree, decision model and budget policy across description variants. Improve description coverage with typical/minority/boundary/language-stratified examples and persist the actual source document IDs. Add bounded recovery using ACL-visible child previews before irreversible pruning.

## Contracts and ownership
1. Coverage worker owns new hierarchy_descriptions.py plus hierarchy.py, hierarchy_models.py and coverage tests. `select_description_samples(documents, *, vectors=None, limit=12)` returns ordered list of dicts `{document_id: str, roles: list[str]}`. Prefer normalized existing semantic vectors for centroid typical/boundary and farthest-first minority diversity; otherwise deterministic content-derived lexical proxies, explicitly labelled. Include language/script strata (metadata.language/lang when present, Unicode script heuristic otherwise). Selection ties use content before ID, do not just take an ID prefix. Unique IDs, no input mutation, bounded positive limit; record inability to cover all strata if limit insufficient.
`assess_description(text: str) -> dict` returns `{weak: bool, flags: list[str]}` for missing/blank, obvious generic (English/Chinese), low-informational text heuristics. These are warning proxies, never calibrated semantic quality. Root recovery may also flag sibling-identical descriptions. Expose `DESCRIPTION_POLICY_VERSION` string.
`LocalHierarchyDescriber.describe_with_provenance(label, documents, *, vectors=None, sample_size=None) -> dict` returns `{text, document_ids, roles, selection_version, generation_version}`; document_ids describe actual samples surviving prompt packing. `.describe()` retains original text-only API. Prompt asks for major AND minority topics and sibling-distinguishing scope, no invented exclusions. Bound fields/context; prefer shorten fields to fit rather than dropping all minority/language exemplars; any unavoidable sample loss must be recorded. No mutable per-call adapter provenance attribute (thread safety). Builder uses method when available; custom text describers receive selected docs and provenance records passed inputs. Extractive fallback uses same diverse sample policy, per-item char quotas so long first title cannot dominate; provenance only includes contributing IDs. Persist `description_provenance` and `description_quality` on groups; optional fields maintain old schema compatibility. Validate provenance IDs are unique descendants, roles shape/versions, nonblank descriptions (reject whitespace). Cache reuse requires current policy provenance; upgrade old artifacts by refreshing descriptions without re-embedding unchanged docs. Canonicalize previous config through defaults to avoid accidental incompatibility for old schema1 artifacts. Diagnostics record weak counts and sampling coverage/provenance warning; no semantic-quality claims. Expose sample-size field in HierarchyConfig if needed (default12), CLI parent handles option.
2. Root owns decision_retriever.py, retrieval/decision.py, recovery tests, docs and final integration. DecisionRetriever gains optional `group_descriptions: dict[group_id,str] | None` replacing only group descriptions in memory (empty override allowed for label-only) while artifact remains immutable. Unknown IDs/nonstring invalid; artifact docs/membership remain source of truth. Active ACL filtering always replaces unsafe stored/override group summaries with visible-only routing text; evaluator documents summaries are bypassed in this mode.
`evidence_paths(*, filters=None) -> dict[passage_id,tuple[node_id,...]]` enumerates visible immutable tree paths, includes group/document/section/passage nodes. IDs remain g/{groupid}, d{document index}, d{index}/s{section index}, docid::passage-N. Model calls not performed.
DecisionRetrieverConfig adds preview_max_nodes=0 (disabled baseline), preview_chars_per_node=600, preview_total_chars=1800, preview_children=4, preview_scan_limit=64. All validated (max_nodes nonnegative, others positive). Preview limits are per query: <=max_nodes replacements, <=total_chars added content, <=chars_per_node each, <=scan_limit visited descendant nodes total, <=preview_children evidence items per node. Only weak/duplicate internal descriptions eligible; only visible descendant evidence; per-item quotas avoid long-title monopoly. Append explicit sampled-not-exhaustive child preview before the existing binary judgment, no extra judge question or expanded beam. Budget exhaustion uses original description and records usage. No hosted model/embedding search. ACL reconstructed titles should use per-title quotas rather than 1600-char first-title domination. `_screen_nodes` accepts same args, trace extended compatibly with default fields previewed_ids, preview_chars, candidate_text_chars. NavigationResult gains usage dict with integer binary_calls/binary_judgments/choice_calls/choice_judgments/candidate_chars/preview_nodes/preview_chars/preview_scan_nodes. Usage counts protocol calls/questions and character proxies, not actual tokenizer tokens or arbitrary architecture forward passes. Update usage before calls and keep per-query state local. Server include_trace returns usage and new preview CLI flags.
3. Evaluation worker owns new description_eval.py, description_eval_cli.py and eval tests. `evaluate_descriptions(artifact, model, cases, variants, config=None, *, topk=5, bootstrap_samples=1000, seed=42) -> dict`. cases list dict `{id,query,gold_passage_ids:[...],filters?:dict}`; require unique nonempty IDs/query/unique nonempty gold IDs and every gold ID known+visible under fixed config (fail fast). Gold labels never influence prompts or descriptions. Variants dict name->group_description overrides mapping; always include stored baseline; empty mapping means stored, empty override string means label-only. Validate variant names/IDs/text. Reuse same exact model instance/config, build separate retrievers over same artifact with overrides; do not mutate or regenerate memberships. Gold paths use retriever.evidence_paths(filters=...). Stage metrics: unconditional survival for each gold ancestor stage (group depth, document, section, passage, choice) with missing stages counted as loss, conditional survival with honest denominators (null if no parent survived), complete ancestor-path survival before leaf scoring, complete-path survival through passage shortlist, and final recall@topk at passage ID level. Handle ragged group depths (not-applicable stage excluded), multiple gold evidence labels and queries where one path survives but others fail. Report per-query records, macro metrics, sample counts/denominators, usage proxies and wall latency; paired differences vs baseline with seeded paired bootstrap95% intervals on per-query metrics. Full config, tree fingerprint (exclude override text; hash memberships/content/segmentation), model class/identity, topk, variants/description fingerprints in report. Model determinism is operator responsibility; CLI local logits model stable. Active ACL filters bypass stored/override summaries: report this explicitly, do not claim comparing those summaries under ACL.
CLI `python -m ...description_eval_cli --hierarchy FILE --queries JSONL --model LOCAL --variants JSON(optional mapname->mapgroupid->text) --output FILE --topk N --beam-width N --group-beam-width N --document-beam-width N --section-beam-width N --preview-max-nodes N [other preview budget flags] --bootstrap-samples N --seed N --device CPU --max-context-tokens N`; built-in variants stored, label_only (empty strings), extractive (diverse sampled titles) without reclustering/regeneration. Optional variants file extends names and forbids baseline collision. Lazy heavy imports; subprocess --help loads no weights. Use actual model API same instance. Output JSON atomically, useful errors; tests injected deterministic judge separate from claimed production results. Root adds API only; worker may temporarily fail tests until root interface lands.

## Constraints and validation
No new dependencies or model downloads in tests. TDD, original139 focused tests retained. Root final fullpytest, ruff, end-to-end offline synthetic evaluation report (explicitly synthetic, no real-quality improvement claim), independent review. Benchmarks report actual costs, same budget policy does not imply identical total compute as different branches have different sizes. No merging PRs automatically.
